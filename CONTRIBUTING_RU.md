# Участие в разработке

Спасибо за интерес к проекту. Перед существенным изменением создайте issue с описанием проблемы и предлагаемого решения.

## Локальная разработка

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m mypy src
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Сохраняйте изменения небольшими и целевыми, придерживайтесь существующей архитектуры и именования, а новое поведение покрывайте регрессионными тестами. Pull request должен проходить Windows CI для Python 3.11–3.14.

## Pull request

- Опишите видимое пользователю поведение и возможные последствия для совместимости.
- Не объединяйте несвязанный рефакторинг с новой функцией или исправлением.
- При изменении поведения или установки обновляйте `README.md` и `README_RU.md`.
- Поддерживайте одинаковое содержание `CONTRIBUTING.md` и `CONTRIBUTING_RU.md`.

## Релизы

Релиз создаётся из чистого рабочего дерева:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\release.ps1 -Version 1.2.0 -Push
```

Каждый успешный push в `main` автоматически создаёт prerelease с уникальным тегом вида `v1.1.0-build.5.1`. Скрипт выше нужен для стабильного релиза: он обновляет версию приложения, выполняет все проверки, при изменении версии создаёт release-коммит и соответствующий тег `v1.2.0`, а с параметром `-Push` отправляет их в GitHub. Push стабильного тега запускает тот же release workflow: он сверяет версию и тег, собирает wheel и архив исходников, после чего публикует обычный GitHub Release с автоматически сформированным описанием.

По умолчанию commit и тег не подписываются, поэтому скрипт работает и без интерактивного GPG-агента. Если GPG настроен и доступен, добавьте `-SignCommit -SignTag`.

Используйте семантическое версионирование: patch для совместимых исправлений, minor для совместимых функций и major для несовместимых изменений.

## Безопасность и приватность

Не добавляйте в issue, коммиты, скриншоты и тестовые данные Telegram-сессии, API key, API hash, номера телефонов, конфигурационные файлы и персональные фрагменты журналов. Если реквизиты уже были показаны, отзовите или замените их до публикации репозитория.
